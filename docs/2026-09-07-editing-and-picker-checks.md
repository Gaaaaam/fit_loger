# 训练录入与选择界面调整

## 已实现

- 新组保持未完成，输入重量和次数只保存数据。完成状态由用户勾选；修改已完成组保留原完成时间。
- 组标签使用 2×2 按钮：正式、热身、递减、递增。
- 部位选择使用可纵向滚动的两列卡片，配套九张本地矢量示意图。
- 新增腹部、核心、有氧分类及八个按次数记录的内置动作。现有数据库启动时幂等补入内置动作，不覆盖旧记录。
- 未完成提示放在滚动区域外，移除新增动作后的延时强制滚动。添加动作、组前清除旧输入焦点，使用稳定的部位、动作和组标识保留组件。

## 分类取舍

腹部侧重卷腹、举腿等腹肌动作；核心侧重躯干稳定、抗旋转，两者生理范围有重叠，并非互斥的解剖部位。有氧是训练类型，因此选择器标题为“训练部位 / 类型”。当前仍按重量和次数记录，有氧先提供跳绳、开合跳，暂不支持跑步或骑行的时长、距离。

四个常用组标签保持不变。现有 RIR 用于描述接近力竭程度，不再增加重复的“力竭组”标签；超级组需要动作之间的关联，不能只加一个单组标签。后续若确有进阶记录需要，可独立设计休息暂停等技法。

参考：[ACSM 2026 抗阻训练说明](https://acsm.org/resistance-training-guidelines-update-2026/)、[ACE 核心训练综述](https://contentcdn.eacefitness.com/SAP-Reports/Core_SAP_Reports.pdf)。

## 自动验证

- `node tools/verify_editing.mjs`：执行真实 ArkTS 状态函数和 SetRow 事件方法，检查连续输入、自动保存、手动完成、取消完成、完成时间及非法输入。
- `node tools/verify_categories.mjs`：检查九个分类读写映射与图片资源，使用真实建表和种子代码验证 SQLite 重复初始化不覆盖已有动作。
- `node tools/verify_v1_logic.mjs`、`node tools/verify_project.mjs`、`node tools/verify_calendar.mjs`：原有逻辑和项目检查。
- DevEco Studio 的 `assembleHap` 编译与打包通过；仍有弃用 API 和异常处理提示。

## 真机验收（尚未执行，无连接设备）

1. 新增组，连续输入重量 `12.5`、次数 `10`：键盘不因首位输入自动收起，圆圈保持未完成。离开页面后回来，数值和状态保留。
2. 手动勾选，再修改重量：仍为完成；取消勾选并重新进入页面：保持未完成。
3. 只剩最后一个未完成组时输入、勾选和取消：页面不跳动，输入框不被重建。
4. 添加至少五个动作，每个三组；编辑最下方动作后向上滚动，在中间动作添加组：不跳回旧输入位置。分别在同一部位和不同部位重复。
5. 滚动到页面中间打开动作选择器，新增动作或取消：不强制滚到部位末尾或旧输入框。
6. 打开标签面板，检查两行两列按钮、当前选中高亮、四种标签持久化，切换标签不自动勾选。
7. 在小屏、大字体和深色模式检查九张部位卡片：两列显示，可滚动到有氧；文字与点击区域正常。
8. 使用已有数据库升级，检查原训练记录不变，腹部、核心、有氧均可选择并添加动作，重启不会重复添加内置动作。
