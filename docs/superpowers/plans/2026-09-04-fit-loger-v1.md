# Fit Loger v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把训练日志 app 的数据地基和录入业务一次做对：版本化迁移、备份导出、v1 schema、预填+打勾、强度信号，以及自建动作 / PR / 撤销 / 体重入口。

**Architecture:** 纯规则（解析、tag 拆分、继承、状态机、PR、导出、分组）抽到可被 Node 验证的逻辑模块；HarmonyOS 层只负责 RdbStore I/O 和 ArkUI。日详情改为局部更新内存模型，不再全量 reload + `viewEpoch` 强制重挂载。

**Tech Stack:** HarmonyOS NEXT ArkTS (`@kit.ArkData` relationalStore), 现有 ets 组件，Node `tools/*.mjs` 静态/逻辑校验（无 DevEco 单测）。

## Global Constraints

- 目标 schema `version = 1`；时间戳 Unix 毫秒整数；日期 `YYYY-MM-DD` 文本。
- `status` 只有 `'planned' | 'done'`；所有聚合查询必须带 `WHERE status = 'done'`。
- 绝不为缺失的 `rir` / `completed_at` 编造默认值；历史数据保持 NULL。
- 迁移前必须 `backup()`；成功后只保留最近 5 份备份。
- 旧表 `day_parts` 与 `*_legacy` 暂不删除。
- 旧 `tag` 拆成 `is_warmup` + `technique`；`rir` 只存 `0 | 1 | 3 | NULL`。
- 自建动作 id：`'usr_' + 时间戳`；`is_builtin = 0`。
- 部位降级为动作属性：`day_exercises` 直挂 `day_id`；UI 仍按 `part_key` 分组。
- v1 不做派生表、趋势页、配重建议、停滞检测、LLM。
- 不改动 `build-profile.json5`（含本地签名密钥）。
- ArkTS 风格与现有代码一致：显式类型、`for` 索引循环、不引入未使用的抽象。
- 用户未要求 commit：实现过程不自动 git commit。

### Task 3: Migration 框架 + 备份 + v1 schema

**Files:**
- Create: `db/schemaSql.ets`, `db/BackupService.ets`
- Modify: `db/WorkoutDatabase.ets`
- Modify: `entryability/EntryAbility.ets`（把 context 交给 BackupService）

**Interfaces:**
- `CURRENT_VERSION = 1`
- `WorkoutDatabase.init(context)`：getStore → 若将迁移则 backup → 跑 migrations → store.version = 1
- Fresh：`version===0` 且无 `day_parts`（或无 `workout_days`）→ 执行第 4 节全部 DDL + seed
- Legacy：`version===0` 且存在 `day_parts` 且 `day_exercises` 仍有 `day_part_id` → 按 spec 5.2 迁移（应用层计算 sort_order，不用窗口函数）
- 幂等：`version===0` 但 `exercises` 已存在且 `day_exercises` 已有 `day_id` → 只把 version 设为 1，不重插数据
- `ALTER TABLE workout_days ADD COLUMN` 前先检查列是否存在
- 备份文件名：`workout_backup_<yyyyMMdd_HHmmss>.db`，保留 5 份

DDL 原文见 spec 第 4 节。`workout_sets` 新列：`is_warmup, technique, rir, status, completed_at, note`；旧 `tag` / `exercise_row_id` 只留在 legacy 表。
